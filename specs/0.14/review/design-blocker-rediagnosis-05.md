# CK 0.14 Design Blocker Rediagnosis 05

Review source: `design-adversarial-review-05.md`

Verdict: all eleven findings are confirmed blockers. The first pass treated the
output grammar's exclusion of `~` as sufficient for destinations, but rediagnosis showed
that an existing Windows short name may be assigned without that character. The
destination must therefore canonicalize an existing alias through its handle to
the authoritative long name. The same path audit also exposed an older
contradiction between parent-traversal rejection and the frozen
`../../fixtures/...` manifest examples; the revision must close it.

## R1. Destination and staged-input namespaces

Confirmed. Existing Windows destinations must canonicalize any requested short-name
spelling to the authoritative long leaf obtained from the opened handle and must
recheck initially absent leaves after lock acquisition. For inputs, the revision
will define a canonical input root and use flat content-addressed staging plus a
bounded logical-to-physical map, so source paths never become temporary path
components and case/normalization aliases cannot overwrite another snapshot.

## R2. Smoke boundary

Confirmed. Artifact size rejection will precede smoke. Smoke will run only for the
bounded size-valid finalists that can enter measurement, matching the terminal
matrix without adding new states.

## R3. Validation derivation

Confirmed. Round summaries will be a pure checked derivation from candidate streams
and calibration records, with exact candidate/case/round cardinality, integer
median and Q32 formulas, weighted aggregation, stability, paired wins, qualifier,
and rank equalities.

## R4. Environment confidentiality

Confirmed. Decision workload environment records will store canonical name,
original byte length, and a domain-separated value digest, not the original value.
The private session snapshot retains the actual bytes for execution. Inspection
therefore exposes identity without exposing secrets.

## R5. Windows argv ABI

Confirmed. The revision will freeze UTF-8 scalar validation, UTF-16 conversion,
the CommandLineToArgvW-compatible inverse quoting algorithm, and a conformance
fixture set. Unix continues to pass the exact accepted bytes as argv elements.

## R6. Cumulative v0.13 evidence

Confirmed. Historical replay evidence and cumulative v0.14 compatibility will be
separate objects and checker modes: immutable historical evidence is checked at its
recorded v0.13 commit, while the cumulative suite runs on the v0.14 candidate SHA
under a candidate-aware schema-8 compatibility mode.

## R7. Equal external work

Confirmed. Every external case record will retain a closed calibration with
attempts and raw elapsed values, select one iterations-per-call value, and require
that value for every channel in all warmup and measured calls.

## R8. Expected correctness

Confirmed. Internal validation rows will bind to the decoded manifest case's
expected digest. External release/domain rows will bind to a frozen expected-result
record whose digest is independently recomputed from the input and canonical result
bytes.

## R9. Channel and decision provenance

Confirmed. Schema 9 will define closed recipes for every named channel, repeated
compilation invocations, fresh cache/output preconditions, and leaf-by-leaf
equalities from decoded decisions to retained compiler, source, workload, target,
profile, runner, manifest, and artifacts.

## R10. Tune-run provenance

Confirmed. Each cold/warm session will be a closed `TuneRun` with exact command,
isolated cache root identity and before/after inventory, raw event log/counters,
decision, and output set. Cold roots are distinct and empty; warm uses cold one's
post-cache state.

## R11. Archive identity

Confirmed. The replay endpoint will equal `v013ReplayBundle.archive`. The candidate
archive will be generated by one closed deterministic packaging command and bound
to a complete three-member manifest containing the statically self-contained
candidate compiler, license, and third-party notices; a separate dependency audit
proves the compiler contains its LLVM/runtime dependencies.

## Acceptance rule

The revision must implement all confirmed corrections without weakening safety,
determinism, performance, or release thresholds. It must pass a fresh ultra Sol
review with zero blockers before implementation planning begins.

## Applied revision

The normative design now implements every item above:

- destination resolution uses long-name/handle identity and a post-lock namespace
  recheck; input staging uses a flat ordinal-plus-full-digest namespace and
  `CK_TUNE_INPUT_MAP`, while frozen manifests use an explicit operational
  `input_root` without logical-path traversal;
- smoke is restricted to size-valid measured finalists;
- every validation summary, entrant, threshold, paired-win count, and rank is
  rederived from the exact raw streams and calibration records;
- public environment identity contains only name, byte length, and a
  domain-separated digest, and Windows argv conversion/quoting has one frozen ABI;
- historical schema-8 replay and fresh v0.14 compatibility evidence are distinct;
- external calibration, per-call iterations/completion receipts, and expected
  result bytes close equal-work and correctness provenance;
- each build channel, repeated compile invocation, decision leaf, output, and
  cache base has a closed foreign-key chain. Cold cache is proved by an exclusive
  empty namespace instead of a version-specific `--no-cache` flag, allowing the
  v0.13 replay compiler and the explicit warm-reuse session to obey one contract;
- `TuneRun` binds commands, cache snapshots, event logs, resource observations,
  decisions, and outputs, and the archive comparison binds both deterministic
  package endpoints and the exact three-member recipe.

## Post-revision self-audit

Result: PASS for this repair round. Each of B1..B11 now has one normative producer,
one closed retained representation, and an independent checker derivation. The
audit also checked the implementation boundary against the existing v0.13 CLI:
cold compilation uses isolated empty platform cache roots rather than unsupported
new flags, and the new schema-8 compatibility mode carries the complete referenced
evidence closure. English and Chinese policy summaries agree with the shared
attachments. No safety, determinism, performance, resource, or release threshold
was reduced. A fresh reviewer must still independently confirm the result.
